# 留言守門（Webhook 自動隱藏洗版留言）設計

- 日期：2026-11-20　- 狀態：待使用者確認
- 前置：Webhook 回呼網址（`server/fb/webhook.js`，已上線、簽章已驗）；臉書 App 已是上線模式（使用者確認）。

## 1. 目的與為什麼
新聞粉專留言區常被「理財詐騙」洗版：帳號先留無害文字（例：「哇哦哦哦哦」），之後**編輯**成標註假理財帳號的推薦文（例：「幸好一直看 💋雙寶爸的財經新報 超讚！」）。小編現在手動**隱藏**。目標是後端收到留言通知就自動判斷並隱藏，省下人工巡留言。

## 2. 目標／非目標／反目標
- 目標：新增與**編輯後**的留言都檢查；命中規則的記錄下來；確認規則可靠後切成自動隱藏；管理頁看紀錄、手動隱藏／取消隱藏、改規則。
- 非目標：刪除留言、封鎖使用者、私訊、數據報表、AI 判斷、回覆留言。
- 反目標（就算能跑也算失敗）：大量誤隱藏一般讀者留言；因留言量大把臉書 API 打到限流、影響排程發布；Webhook 回應太慢讓臉書停用訂閱。

## 3. 已知的洗版特徵（來自使用者範例）
| 特徵 | 例 |
|---|---|
| 先留無害字再編輯成廣告 | 「哇哦哦哦哦」→「幸好一直看 💋雙寶爸的財經新報 超讚！」 |
| 標註一個帳號（個人帳號改名成像粉專） | `@三寳爸飆股日記`、`@雙寶爸的理財週刊`、`@寶爸生活理財筆記` |
| 標註名稱格式 | 三寳爸／雙寶爸／寶爸＋理財／股／投資／筆記／週刊／日記 |
| 吹捧＋引導句型 | 選股超厲害、進群跟老師學、獲利、值得追蹤、強推這個交流群 |

## 4. 做法比較（使用者選 A＋做法 1）
**上線策略**：A 先觀察再開啟（選）／B 直接自動隱藏。
**接收方式**：
| 做法 | 取捨 | 結果 |
|---|---|---|
| 1. Webhook 即時：先用通知裡的留言文字預篩，命中才向臉書讀那則留言的標註 | 即時、抓得到編輯；大部分留言 0 次 API | **選用** |
| 2. 定時巡查最近貼文留言 | 新聞粉專留言量大 → API 用量爆、曾因每分鐘對時被限流；編輯要等下一輪 | 不用 |
| 3. Webhook＋每日補掃 | 補掃同樣有用量問題，目前沒需要 | 不用 |

## 5. 設計
### 5.1 模式（全域，一個設定）
`off` 關閉／`observe` 觀察（只記錄，不隱藏）／`hide` 自動隱藏。第一次開啟預設 `observe`。

### 5.2 哪一組權杖、哪些粉專
- 管理頁選「守門用組別」（權杖組別之一；預設自動選第一個有 `pages_manage_metadata` 的組別）。這組的 App 才收得到通知（臉書依 App 推送），隱藏也用這組的粉專權杖；**不跟著發文使用中組別切換**（使用者有兩組權杖，只有一組有 `pages_manage_metadata`）。
- 每個粉專一個開關：開＝`POST /{page}/subscribed_apps?subscribed_fields=feed`（該粉專權杖），關＝`DELETE /{page}/subscribed_apps`。管理頁顯示各粉專目前是否已訂閱（`GET /{page}/subscribed_apps`，按「重新檢查」才查）。
- Meta 後台 Webhooks 的 Page 物件要訂閱 `feed`（主管手動，管理頁卡片寫提示）。

### 5.3 收到通知的處理（`/fbhook` POST，簽章驗過之後）
1. 只處理 `object=page`、`changes[].field=feed`、`value.item=comment`、`value.verb ∈ {add, edited}`；粉專不在「已開啟」清單、或留言者是粉專本身（`from.id == page id`；通知沒附 `from` 就在第 3 步讀到後再檢查）→ 略過。
2. **預篩（不打 API）**：`value.message` 含任一「名稱關鍵字」或任一「引導詞」才繼續；否則結束。
3. **讀留言**：`GET /{comment_id}?fields=message,message_tags,from,is_hidden,permalink_url`（守門組別的粉專權杖）。
4. **判斷**（命中任一即為命中）：
   - 規則 1：`message_tags` 中有名稱含「名稱關鍵字」的標註。
   - 規則 2：有任何標註，且留言含 ≥2 個不同「引導詞」。
   - 例外：留言者 ID 在「白名單」→ 不命中；紀錄標「豁免」的留言（手動取消隱藏過）→ 不再處理。
   - **每條規則各自有「自動隱藏」開關**（〔實作者判斷〕）：規則 1 預設開、規則 2 預設關（一般讀者標朋友＋說「追蹤／獲利」可能誤中）。模式 `hide` 時，只有開關打開的規則會真的隱藏，其他命中仍只記「觀察」。
5. 命中 → 寫紀錄；模式 `hide` 且 `is_hidden=false` → `POST /{comment_id}?is_hidden=true`，紀錄動作＝已隱藏／失敗。模式 `observe` → 動作＝觀察（若開啟會隱藏）。
6. 編輯後不再命中的已記錄留言：不自動取消隱藏，紀錄加註「已編輯」。管理頁手動「取消隱藏」＝該則標「豁免」，之後再編輯也不再自動隱藏（尊重人工判斷）。
7. 先回臉書 200，再背景處理（`ctx.waitUntil`）；任何錯誤吞掉、記錯誤日誌，不影響回應。
8. 用量保護：讀留言／隱藏走既有 `graph()`（會記速率用量）；速率限制卡片顯示 ≥90% 或被限流時，暫停讀留言（只記「預篩命中但未檢查」），避免影響排程發布。

### 5.4 規則設定（管理頁可改，D1 `fb_settings` k=`guard_rules`）
- 名稱關鍵字（預設：寶爸、寳爸）
- 引導詞（預設：老師、進群、交流群、選股、飆股、獲利、追蹤、帶單、理財群）
- 白名單留言者 ID（預設空）
- 每類最多 50 筆、每筆 ≤20 字；比對前文字統一全形／半形與大小寫。

### 5.5 紀錄（D1 新表 `fb_guard_log`，自動建立）
欄位：留言 ID（主鍵）、粉專、貼文 ID、留言者名稱與 ID、留言內容（≤500 字）、標註名稱、命中規則、動作（觀察／已隱藏／隱藏失敗／手動隱藏／已取消隱藏）、是否編輯過、時間、連結。**保存 30 天**（既有每日 cron 清除）。
> 這會存讀者留言內容：隱私權政策（中英）要補一列（用途：判斷洗版，保存 30 天）。

### 5.6 管理頁「留言守門」卡片（`admin/`，分類「臉書發文」）
- 上方：模式三選一（關閉／觀察／自動隱藏）、守門用組別下拉、Meta 後台提示。
- 粉專清單：只列守門組別換得到粉專權杖的粉專（〔實作者判斷〕其他組才有的粉專不列，無法開）；開關＋訂閱狀態＋「重新檢查」。
- 規則：三個清單編輯（同活動留言的編輯方式）＋儲存。
- 紀錄：最新 50 筆、可篩動作與粉專、載入更多；每列內容、命中規則、連結開新分頁；按鈕「隱藏」（觀察模式下手動執行）／「取消隱藏」。
- 卡片代號 `guard`（不屬敏感卡片，模式切換不另外要求解鎖〔實作者判斷〕：系統管理者可在「層級權限」收回）；預設**管理者有、普通沒有**。路由 `/admin/fb/guard*` 加進 `ROUTES`。
- 手動隱藏／取消隱藏、改模式寫進既有操作紀錄（`fb_audit`，沿用其記錄者欄位；動作名稱「隱藏留言／取消隱藏留言／留言守門模式」）。

## 6. 限制
- 臉書 `feed` 通知的留言應附 `message`、編輯為 `verb=edited`（依官方欄位說明推論，未實測）。〔實作者判斷〕若某則沒附 `message`：**不讀留言**（避免新聞粉專大量讀取），只累計「無文字通知」次數顯示在卡片上；觀察期若此數字明顯偏高，再回頭決定要不要加「限量讀取」。
- 只對開啟後的新留言／新編輯有效，不回頭掃舊留言。
- 對方改用不含關鍵字的名稱就抓不到 → 靠觀察期與管理頁調整關鍵字。

## 7. 留給實作者決定
- 檔案切分（建議新檔 `server/fb/guard.js`，`webhook.js` 只加一個呼叫掛點）、`ctx` 如何傳進 `handleFbHook`。
- 管理頁紀錄列表的排版細節（沿用活動留言／操作紀錄的樣式）。
- 測試：單元（預篩、判斷、模式、白名單、編輯流程、限流暫停、30 天清除）＋admin e2e（卡片操作，臉書以替身）。

## 8. 部署
後端需重新部署（正式＋測試），自動建表，不用手動 SQL；外掛不升版號。部署後：主管在 Meta 後台 Webhooks 的 Page 訂閱 `feed` → 管理頁選守門組別、開粉專 → 觀察幾天 → 切自動隱藏。
