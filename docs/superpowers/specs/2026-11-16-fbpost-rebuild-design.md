# 排程發布（fbpost）重寫設計

- 日期：2026-11-16　- 狀態：待使用者確認（審查問題已回覆）
- 原則：**完全不參考舊版排程發布的程式、交接檔、規格紀錄**（使用者指示）。共用的 SDK（`sdk/news-article.js`、`sdk/news-rules.js`）與「圖片套版」（`tools/pattern/`）是現役程式，可以用；`sdk/news-sched.js` 是舊版留下的，不用。
- Rundown 的 Apps Script 依據：`unnn3ing-oss/-schedulenewnet` 的 `gas/rundown.gs`、`worker/index.js`（現役、使用者指定）。

## 1. 目的
小編拿到一則公司新聞網址後，在同一個視窗內：做好套框圖片 → 組好貼文文字 → 勾選多個粉專、各自決定立即或排程與時間 → 一次送出到臉書；貼文發布後自動在第一則留言補「看更多新聞內容＋連結＋該粉專 UTM」；可選擇同時寫入 FB RUNDOWN 試算表。之後在工具裡看已排程／已發佈、改時間、取消、刪除。

## 2. 目標／非目標／反目標
- **目標**：上面整條流程；排程貼文**要出現在臉書後台「已排定」列表**（驗收項目，只能部署後實測）。
- **非目標**：AI 產生小編文、校錯字（使用者明確不要）；第 2 則以後的留言；網新排程；外掛改版。
- **反目標**（做出來但算失敗）：發出去的貼文缺圖或變成無圖貼文；留言補錯粉專的 UTM；RD 寫入失敗導致臉書送出被當作失敗；同一筆因重試被重複發文或重複留言。

## 3. 使用者流程與畫面

### 3.1 新增發文視窗（參考使用者提供的截圖）
```
┌ 新增發文  [作圖框｜純文字底圖]                              (×) ┐
│ ┌──────────────┐  文章網址 [_____________________] [帶入]       │
│ │ 1080×1080 預覽 │  標題（自動換行）                              │
│ │ 套框＋貼圖／馬賽克│  貼文內容（框內即實際發出的文字）             │
│ └──────────────┘                                                │
│ [新聞藍框｜娛樂粉框]  ┌ 發到哪些粉專 ───────────────────────┐    │
│ 貼圖／馬賽克列         │ ☑ 1 新聞   (●立即 ○排程)                │    │
│                        │ ☑ 2 少康   (○立即 ●排程) [日期] [時間]   │    │
│                        │ ☐ 3 娛樂   (●立即 ○排程)                │    │
│                        └────────────────────────────────┘    │
├──────────────────────────────────────────────────┤
│ (●)排入 Rundown  SLUG [__________]      [全部送出（2 個粉專）]       │
└──────────────────────────────────────────────────┘
```
- 相對截圖的位置調整（使用者指定）：**粉專勾選**移到右側原本 Rundown 框的位置；**排入 Rundown** 移到底部「全部送出」左邊，**開關在左、SLUG 輸入框在右**。
- 不放 AI 產生、校錯字按鈕。

### 3.2 做圖（沿用「圖片套版」）
- 作圖框／純文字底圖、新聞藍框／娛樂粉框、標題換行、T寶貼圖、馬賽克：功能與規則和「圖片套版」一致。
- **標題換行**依「圖片套版」的規則（`sdk/news-rules.js` 的 `autoLines`）。
- **框的自動判斷（本工具專用）**：網址 `news.tvbs.com.tw/<類別>/<文章ID>` 類別是 `sports` 或 `entertainment` → 娛樂粉框，其他一律新聞藍框。可手動切換。「圖片套版」現行規則（只有 entertainment）**不改**，除非使用者另外要求。
- 公司素材（框、Logo、T寶）一樣只從後端取得，沒有公司憑證時不出現公司字樣。

### 3.3 帶入（貼網址）
- 後端現有 `/fetch/article`、`/fetch/image`；解析用 `parseArticle`。
- 帶入後：標題 → 標題欄（自動換行）；第一張可用圖片 → 預覽；貼文內容框自動組好（見 3.4）。

### 3.4 貼文內容格式
```
小編文
【標題（單行）】
（第一張圖片的圖說）
#標籤 #標籤 #標籤
```
- 使用 `sdk/news-article.js` 的 `formatCopy`／`pickTags`（hashtag 只取 2～3 字、不互相包含、最多 3 個，不夠不補）。
- 第一行留給小編文，預設空白；**小編文沒填時整行拿掉**，貼文從【標題】開始。
- 沒有圖說（例如純文字底圖）→ 圖說行省略。
- 框裡的文字就是實際發出的文字，可自由修改。

### 3.5 粉專區塊
- 粉專清單來自後端（由臉書 user token 讀出可管理的粉專），依管理頁的順序與序號顯示**簡稱**。
- 每列：勾選＋序號＋簡稱＋「立即／排程」；選排程才出現日期與時間，預設現在＋30 分鐘。
- 排程可選範圍：**10 分鐘～30 天**（Meta Pages 文件寫 30 天、Feed 參考寫 75 天，取保守的 30 天）。時間一律本機時區。

### 3.6 送出
- 「全部送出（N 個粉專）」：依每個粉專各自的設定分別立即發布或排程。
- 送出中顯示每個粉專的進度；結束後每個粉專一列結果（成功／失敗＋原因）。部分失敗時只重送失敗的粉專。
- 有圖時一律是**一張圖＋文字**的相片貼文。

### 3.7 第一則留言
```
看更多新聞內容
https://news.tvbs.com.tw/sports/4051394?&utm_source=facebook&utm_medium=2100roomcomments
```
- 連結＝文章網址＋該粉專在管理頁設定的 UTM。網址本身沒有 `?` → 接 `?&utm_...`（照使用者範例原樣）；已經有 `?` → 接 `&utm_...`；UTM 空白 → 只放網址。
- 立即發布：發文成功後馬上留言。
- 排程發布：貼文**實際發布後**才留言（機制見 §5.3）。
- 沒有文章網址 → 不留言。留言失敗不影響貼文結果，在列表上看得到留言狀態與原因。

### 3.8 排入 Rundown
- 開關記在瀏覽器（localStorage），預設關。SLUG 規則（使用者提供）：
  - 手動填：只留文字和數字（去掉空白、標點、符號）。
  - 留空：標題前 4 字（去符號）；標題第一行有 `/`／`／` 時只取第一個斜線後的字（後面沒字就用整行）；第一行只有「快訊」「最新」「新」這類標籤時改從下一個有字的行取。
- 內容：`文章ID/圖文/SLUG`（例 `4046330/圖文/秋冬衣櫃`），文章 ID 取網址最後的數字。類型一律 `圖文`。
- 臉書送出或排程**成功**的粉專，且該粉專在管理頁有設定 RD 區段，各寫一筆；時間＝該粉專的發布時間（立即＝送出當下）。
- 顯示結果一句話，例「主粉 15:13 → AE255（插入）」。RD 失敗不影響臉書結果。

### 3.9 已排程／已發佈管理（工具內分頁，隱藏切換）
- **已排程**：各粉專的排程貼文（縮圖、文字摘要、排定時間、留言狀態）；可**改時間**、**取消**。
- **已發佈**：各粉專最近發佈的貼文（縮圖、摘要、發佈時間、連結、留言狀態）；可**刪除**。
- 資料一律**向臉書查詢**，按「刷新」才查，以臉書實際狀態為準；改時間、取消、刪除後同步更新留言排程。
- 可以依粉專篩選。

### 3.10 值班粉專（使用者要求）
- **每天第一次打開「排程發布」**時跳出「選擇今天的值班粉專」視窗（可複選、可略過；工具內另有按鈕可隨時重選）。
- 選了的粉專在新增發文的粉專清單**排在最前面**（維持管理頁順序與序號，只是值班的在前）。
- 值班狀態存在瀏覽器（localStorage），**換日後本機時間清晨 01:00 起失效**，之後第一次打開再跳出。
- **第一個選的值班粉專＝主要粉專**（選單上標示「主要」）：新增發文時**預設勾選**主要粉專；其他值班粉專只排前面、不預設勾選。勾選後仍可手動取消。
- 值班不影響發布方式與時間。

### 3.11 Rundown 與改時間／取消
- 排程貼文改時間或取消後，**不處理** RD 已寫入的格子（使用者決定，Apps Script 也只能新增）。

## 4. 管理頁（`admin/` 與後端 `/admin` 都加）
- **臉書連線**：顯示 token 狀態（有效／到期日／缺少的權限），按鈕「重新讀取粉專」。token 本身只在 Secrets（見 §5.1），管理頁不能貼或看到 token。
- **粉專設定**：每個讀到的粉專一列，可改：
  - 簡稱（只影響網頁顯示）
  - UTM（只影響留言連結）
  - RD 區段：主粉／娛樂粉／少康粉／國際＋粉／不寫入
  - 順序（決定序號）
  - **顯示**開關：關掉的粉專不出現在新增發文與值班粉專選單（使用者同意）
  - 新粉專：簡稱預設＝臉書粉專名稱、UTM 空白、RD 不寫入、顯示開。
  - 初始值（使用者提供，部署後在管理頁填）：新聞 `?&utm_source=facebook&utm_medium=fbarticlepic`；少康 `…2100roompic`；娛樂 `…tvbsteatimenewspic`；國際+ `…tvbspluspic`；擠看看 `…gkkcomments`；氣象未提供（空白）。
- **Rundown 連線**：顯示是否已設定、按「測試連線」（ping，回試算表名稱與前 6 個分頁）。

## 5. 後端（`toolbox-api`）

### 5.1 Token（使用者選 2B：存 Cloudflare Secrets）
- Secret `FB_USER_TOKEN`（長效 user token）。後端用 `GET /me/accounts` 換各粉專 page token，暫存在記憶體／KV（不寫 D1）。
- 長效 user token 約 60 天會過期（Meta 文件），換 token ＝ `wrangler secret put FB_USER_TOKEN`；管理頁顯示到期日提醒。
- 需要的權限：`pages_show_list`、`pages_manage_posts`、`pages_read_engagement`、`pages_manage_engagement`、`pages_read_user_content`。

### 5.2 臉書呼叫（Graph API，以 Meta 官方文件最新版為準，目前 v27.0）
| 動作 | 做法（官方文件） |
|---|---|
| 立即有圖 | `POST /{page-id}/photos`（`source`、`caption`） |
| 立即純文字 | `POST /{page-id}/feed`（`message`）——純文字底圖仍是有圖貼文，此路徑只在完全沒圖時用 |
| 排程有圖 | 官方唯一範例：`POST /{page-id}/photos`（`published=false`、`temporary=true`）→ `POST /{page-id}/feed`（`message`、`attached_media[0]`、`published=false`、`scheduled_publish_time`、`unpublished_content_type=SCHEDULED`） |
| 列表 | 已排程 `GET /{page-id}/scheduled_posts`；已發佈 `GET /{page-id}/feed` 或 `published_posts` |
| 改時間 | `POST /{post-id}`（`scheduled_publish_time`）——**官方文件沒寫，第一段實測** |
| 取消排程 | `DELETE /{post-id}`——**官方文件沒寫，第一段實測** |
| 刪除已發佈 | `DELETE /{post-id}` |
| 留言 | `POST /{post-id}/comments`（`message`，page token） |
- **第一段（使用者選 3A）**：先做後端＋管理頁的臉書連線與粉專設定＋**在 `fbpost` 工具本身**（未來的正式頁面）做最小的發文與管理功能，使用者實測：排程有圖是否出現在「已排定」、改時間、取消、刪除、留言。
  - **測試期間的進入權限**：只有在網站主頁「登入公司帳號」輸入**管理密碼**（帶 `adm:1` 的公司憑證）才能進入 `fbpost`；用公司密碼或沒登入的人仍看到「功能停用」。後端 `/fb/*`、`/rundown` 測試期間也只接受 `adm:1` 憑證。正式開放時改成一般公司憑證即可（一處設定）。
  - **通過標準（使用者定）**：排程有圖貼文在**臉書後台「已排定」列表與工具「已排程」都看得到圖片預覽**。不符合就暫停，回來和使用者討論，不自行換做法。

### 5.3 排程留言（使用者選 1B：Durable Object 計時器）
- 新 Durable Object 類別（名稱不可用已刪除的 `CommentHub`），SQLite 儲存；每一則排程貼文一筆：粉專、貼文 ID、留言內容、排定時間、狀態、嘗試次數。
- 排程成功時建立並 `setAlarm(排定時間＋緩衝)`；到點先問臉書貼文是否已發佈：
  - 已發佈 → 留言 → 標成功。
  - 還沒發佈（例如被改時間）→ 依臉書上的新時間重設鬧鐘。
  - 貼文不存在 → 標已取消。
  - 臉書錯誤 → 有限次數重試（間隔遞增），限流錯誤不重試；最後標失敗並保留原因。
- 工具內改時間／取消／刪除時同步更新或移除該筆。
- **不可重複留言**：留言成功的狀態要先寫入再結束；重試前先確認是否已經有自己留過的留言（或用狀態保證最多一次）——細節由實作決定，但驗收必須涵蓋。
- 部署：`wrangler.toml` 需新增 DO 綁定與 `[[migrations]]`；使用者公司電腦的 `wrangler.toml` 已有 v1（new_sqlite_classes）、v2（deleted_classes `CommentHub`），新類別要用 **v3**，repo 版與部署說明要寫清楚。

### 5.4 Rundown 轉送
- `POST /rundown`（公司憑證）：驗格式後補 `RUNDOWN_TOKEN` 轉 `RUNDOWN_URL`。格式與 `-schedulenewnet` 一致：`{ action:'add', entries:[{ page:'news'|'ent'|'shaokang'|'intl', date:'YYYY-MM-DD', time:'HH:mm', text }] }`，最多 10 筆、text ≤100 字不可換行；`action:'ping'` 僅管理憑證。
- `RUNDOWN_URL` 必須符合 `https://script.google.com/macros/s/<id>/exec`。Apps Script 不改。
- RD 區段代號對應：主粉 `news`、娛樂粉 `ent`、少康粉 `shaokang`、國際＋粉 `intl`。

### 5.5 資料（D1）
- 新表存粉專設定：粉專 ID、簡稱、UTM、RD 區段、順序。沒有其他貼文紀錄表（列表直接查臉書；留言佇列在 Durable Object）。

### 5.6 權限
- 測試期間（第一段起到正式開放前）：`fbpost` 與 `/fb/*`、`/rundown` 只給 `adm:1` 憑證（見 §5.2）。正式開放後：`fbpost` 改 `tier: company`，`/fb/*`、`/rundown` 接受一般公司憑證。管理頁 API 一律需要管理憑證。
- 新 Secrets：`FB_USER_TOKEN`、`RUNDOWN_URL`、`RUNDOWN_TOKEN`。

## 6. 方案比較（已選）
| 決定 | 選項 | 選擇與理由 |
|---|---|---|
| 排程後補留言 | A 每分鐘 cron 查 D1／**B Durable Object 計時器**／C 臉書 Webhook | 使用者選 B：準時到秒；代價是部署多一個 DO 綁定與 migration |
| Token 存放 | A 管理頁貼上存 D1／**B Cloudflare Secrets** | 使用者選 B：最安全；代價是換 token 要下 `wrangler secret put` |
| 開發順序 | **A 先驗證臉書再做畫面**／B 一次做完 | 使用者選 A：先排除「已排定列表」等不確定 |

## 7. 驗收
- 單元：貼文格式、hashtag、留言連結＋UTM（`?&`／`&`／空白）、框判斷、SLUG 規則、RD entries、排程時間範圍、DO 狀態轉換（已發佈／改時間／不存在／錯誤／不重複留言）。
- e2e：新增發文視窗版面（粉專在右、RD 在底部左側）、每粉專立即／排程切換、送出結果、已排程／已發佈分頁的改時間／取消／刪除（臉書以替身模擬）。
- 實機（使用者）：第一段的臉書實測清單；第二段完成後用正式粉專各發一則。

## 8. 設計者已定（審查後補，使用者可推翻）
- **Durable Object 結構**：每則排程貼文一個 DO 實例（以貼文 ID 命名），各自一個鬧鐘；改時間／取消／刪除時用貼文 ID 找到它。
- **時間與時區**：日期、時間由前端以本機（台灣）時間算好送後端；立即發布的 RD 時間＝前端按下送出的時間。
- **留言時效**：排定時間＋60 秒第一次檢查；臉書錯誤最多重試 5 次、間隔遞增，補留言最晚約在排定時間後 15 分鐘內完成或標失敗；限流錯誤不重試。
- **多粉專送出**：依序逐一送（不並行），避免臉書限流；`/feed` 失敗時暫存照片不清理（臉書約 24 小時自動刪）。
- **Token 狀態**：用 `GET /me/permissions` 顯示缺少的權限；到期日嘗試用 `debug_token`，查不到就顯示「到期日不明」。不新增 `FB_APP_ID`／`FB_APP_SECRET`。

## 9. 留給實作決定
- 「圖片套版」的繪圖程式怎麼讓本工具共用（抽成共用模組或其他方式），前提是**圖片套版的行為與測試完全不變**。
- 列表分頁大小、縮圖來源欄位、錯誤訊息文字、page token 暫存位置與時效。
- 外掛側邊欄嵌入的 `panel.html?tool=fbpost` 會自動顯示新版，版面在窄寬度下的排列。
