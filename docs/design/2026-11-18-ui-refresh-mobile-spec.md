# 小編工具箱手機介面規範（必要交付）
- 更新：2026-11-18（Asia/Taipei）
- 狀態：設計文件補充，手機 UI 尚未實作／驗證。
- 主規範：[UI refresh spec](2026-11-18-ui-refresh-spec.md)
- 目的：手機採用適合觸控與小螢幕的操作布局，不只是把桌面左右兩欄縮小。
- MUST 為必要；SHOULD 為可依實測調整的預設。手機以本文件較具體條款補充主規範 §7–9；桌面仍採單列分類 A 下拉。

## 1. 適用條件與版面
- 寬度 ≤820 CSS px 進入窄屏布局；≤480px 採單手操作密度；橫向與平板不能只用裝置名稱判斷。
- 寬度與輸入能力分開：觸控裝置即使 >820px，分類按鈕仍可點擊開啟；hover 只在 (hover:hover) and (pointer:fine) 使用。
- 手機保留同一個 URL、工具資料與功能核心，不建另一套手機網站或分叉保存邏輯。
- 沿用主規範白／灰／藍 tokens、8px 控制項圓角、10px 卡片圓角。
- 輸入文字至少 16px，行高 1.5；避免 iOS 輸入自動放大。正文建議 15–16px，次要說明 ≥13px。
- 觸控目標至少 44×44px，常用主動作 48px 高，相鄰小按鈕間距至少 8px。
- 左右外距 16px（320px 時允許 12px）；不使用固定桌面 min-width 造成整頁水平捲動。

## 2. 單列頂部導覽與工具選單
- header 內容列高 56px，另外處理頁面實際需要的 top safe area，避免重複加安全距離。
- 左側品牌可回首頁；右側「工具」按鈕及登入／帳號入口。不再擠入九項工具或常駐第二排分類。
- 公司素材／連線完整狀態放在工具面板內的狀態區，關鍵到期／失敗在工作頁保留精簡提示與入口。
- 點「工具」開啟非模態 disclosure 浮層，距左右邊至少 12px，寬度不超過 viewport 減 24px。
- 面板內依序為「工具首頁」、「做圖」六列、「發文與素材」三列，全部沿用 catalog；圖示＋名稱，當前項淡藍底＋勾選。
- 可視高度不足時僅面板內捲，max-height 使用當前可用視窗高度減 header 與邊距；不要遮到關閉入口。
- 非模態面板不加 aria-modal 或假 focus trap；展開時 aria-expanded 更新，鍵盤可走訪。
- 再點工具、點面板外、按 Escape 可關閉；Esc 回觸發鈕，點選工具則進可見工具內容入口。
- 按鈕到面板沒有只能滑鼠通過的「hover 走廊」限制；切工具後面板關閉。
- 不用整頁透明遮罩阻斷 iframe，卻沒提供合理關閉；外部 iframe 點擊／focus 需實際驗證。

## 3. 首頁：一欄緊湊入口
- 不顯示桌面大型裝飾縮圖；每張卡約 96–120px 高，名稱＋一行用途，必要狀態可換行、不被固定高度裁掉。
- 仍是「做圖」與「發文與素材」兩組、共九項，不因手機藏掉工具。
- 首頁標題 24px，卡片名稱 16px／600。3 欄在平板變 2 欄、手機 1 欄。
- YT 使用條件與排程管理員限制在卡片上可辨識。手機可見工具不等於手機可執行所有桌面助手能力。
- 搜尋如有實作，為全寬 44px 以上輸入框、有 label 與清除鈕，輸入鍵盤不遮結果。
- 保留正常頁面捲動；回首頁再進既有工具不得清空該工具內容。

## 4. 圖片套版手機工作區：局部「編輯／預覽」切換
窄屏製圖頁採單欄，預設「編輯」；工具名稱下顯示局部的「編輯／預覽」切換。這是當前工具內容的一部分，不是第二層全域工具列，不可再列出其他工具。

```text
[編 小編工具箱]              [工具 ▾] [登入]
圖片套版
[編輯] [預覽]                 ← 只切本工具內容
編輯：網址帶入、照片、標題、主色與進階設定
  或
預覽：等比畫布、貼圖／馬賽克、本次圖片縮圖
─────────────────────────────────────
[產生此張] [下載這張] [更多]   ← 必要時換行，避開安全區
```

- 編輯／預覽共用同一份狀態與 DOM；切換使用 hidden，不複製表單、canvas、iframe，不重新載入照片／字型。
- tabs 若採 ARIA tab pattern，需 aria-selected／aria-controls、對應 tabpanel、方向鍵；非選中頁不可被 Tab 聚焦。
- 手機與桌面斷點來回、旋轉、登入狀態改變不應丟內容；回到桌面恢復左右並列。
- 產生成功可切到預覽；產生失敗留在編輯，聚焦／捲到錯誤。單純輸入不自動切頁或跳動。
- 只有能維持完整能力的製圖工具才套這個局部切換；LINE 的既有步驟不能被粗暴改成兩頁。

### 編輯頁
- 網址輸入全寬，帶入鈕可同列或下一列，不縮成難點的小圖示。
- 依背景／標題／主色分組；進階欄位可收合但可達，預設不收起有錯誤的欄位。
- 上傳支援系統檔案／相簿選擇，不要求拖放或 Ctrl+V；相機僅在既有功能支援時提供，不強迫拍照。
- 長標題可換行、textarea 可擴展，保留最多 4 行等既有驗證。
- 色票視覺可 24–28px，但觸控區域 44px；選中有外框／勾選及可讀名稱。

### 預覽頁
- 畫布使用可用寬度減左右間距，預設 contain 完整顯示。390px 視窗左右 16px 時，方形可用寬約 358px。
- 1080×1080 等真實輸出維持原解析度，CSS 顯示縮放不降低匯出尺寸。
- 預覽、貼圖與馬賽克支援 touch/pointer；座標依顯示矩形與實際畫布比例換算，含旋轉、滾動及 devicePixelRatio。
- 不在整個頁面設定 touch-action:none，不攔截瀏覽器縮放；僅必要的畫布手勢區適當處理。
- 拖曳不是唯一調整方式：既有可調位置／大小／刪除屬性以觸控可操作控制提供。
- 本次圖片列用約 64–80px 縮圖，只有此列橫向捲動；當前項有外框＋編號，切換後可見。
- 不加只有外觀卻無功能的縮放／分享按鈕。

## 5. 底部動作與螢幕鍵盤
- 製圖局部操作列：主動作「產生此張」、次動作「下載這張」、更多內保留「全部下載」等既有動作。
- 320px 放不下時允許兩列或把次要項放更多，不截斷文字、不縮小點擊區域；更多須可及並能關閉。
- 預設使用當前工具內容容器內的 sticky footer；不盲目在 iframe 內 fixed 到全域視窗。
- 實作前確認 shell iframe 高度與實際捲動主體：若 sticky 無法保持可見，先調整單一捲動容器；若仍需 fixed，明確記錄容器與定位方式並驗證真機，不能假定 iframe viewport 等於手機可視區。
- 內容預留操作列實際高度＋bottom safe area，最後一個欄位、錯誤與縮圖不能被蓋住。
- safe-area-inset-bottom 只由一個層級消費；避免 shell 與 iframe 都加造成雙倍空白。
- 優先使用 min-height 與 100dvh 的漸進增強，保留 fallback；不要用不可縮的 100vh 卡死地址列與鍵盤。
- 鍵盤打開時，焦點欄位、標籤與錯誤可見；操作列無法避讓時退回正常流，不將輸入區壓成窄縫或蓋住鍵盤上方欄位。
- 不停用頁面縮放、不自動重設捲動位置。首個錯誤顯示 inline 並可聚焦，toast 不能是唯一錯誤訊息。

## 6. 其他工具的手機適配
| 工具 | 必要手機設計 |
|---|---|
| LINE 推播 | 保留版型／格子編輯／檢查步驟；格子點一下顯示複製連結按鈕，不能只用 hover；UTM 與輸出不變 |
| 拼圖 | 預覽與設定能切換或上下布局；選框／照片狀態明確；既有框尺寸／位置控制可觸控操作 |
| 浮水印 | 照片清單、Logo 設定與預覽分區；四角定位有 44px 選項；滑桿與數值可操作 |
| 尺寸 | 寬高與單位 label 不擠壓；數字輸入用合適 inputmode；裁切／等比方式、格式及批次狀態完整 |
| 設計 | 畫布優先，屬性／圖層用局部抽屜或分頁；保留多頁、群組、遮色片、復原／重做、JSON 存取，不以隱藏功能達成極簡 |
| 直播需求單 | 貼上直播單→逐場補欄位→輸出，上下單欄；粉專勾選整列可按；缺漏定位至對應場次／欄位；複製失敗可手動選取文字 |
| 排程發布 | 仍限授權管理員；表單與日期時間不超出 320px；查詢列表保留狀態／時間／操作，次要操作收合不消失；不自動查詢或發文 |
| YT 批量下載 | 如當前手機環境不具所需外掛／桌面助手，明確說明「此功能需在已安裝外掛與下載助手的電腦使用」；顯示條件與教學，不引導在手機執行桌面安裝檔、不假裝連線成功 |

- 一般製圖、直播需求單等不需外掛的功能，不能被手機上不存在的助手阻擋。
- 下載與剪貼簿均由明確使用者操作觸發。Safari／LINE 瀏覽器可能預覽而非直接存相簿，提示實際保存方式，不能宣稱已存相簿。
- Web Share 屬可選增強，只有支援且有使用者操作時出現；取消不是成功，不以此替換必要的原下載流程。
- 批次下載受瀏覽器限制時提示實際失敗與可用單張方式；不可假承諾多檔已全部保存，也不為此修改原圖片格式。

## 7. 實作與交接順序
1. shell 單列 header 與工具面板先完成桌面 click／手機 touch；全域只保留一層。
2. 首頁一欄卡片及真實狀態；驗證 320px。
3. pattern 同步交付桌面左右區與手機編輯／預覽、底部動作；不是桌面做完後才擠壓成手機版。
4. 查驗 iframe 捲動主體與 iOS 鍵盤，解決 footer／安全區後再複用。
5. 其餘工具依 §6 逐一驗證，保留相同資料與渲染邏輯。
6. 更新 handoff 已完成範圍與真機結果；沒有設備要列未驗證，模擬器不能替代真實 Safari／LINE 證據。
