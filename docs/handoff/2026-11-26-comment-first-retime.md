# 留言先留再查＋列表校正計時器＋10 分鐘刷新＋錯誤紀錄複製
- 狀態：完成，待使用者確認後推 main　- 分支：claude/zealous-euler-v7417y　- 最後更新：2026-11-26
- 使用者原始需求：「文章被改往後發也已經成功發布，但還是會通知失敗」；錯誤紀錄＝「留言：找不到這個物件（臉書碼 100-33）」。要「先直接留一次，失敗後才查詢貼文狀態，也可用使用者當前列表讀取是被往後還往前」、列表 10 分鐘自動刷新、錯誤紀錄可複製。

## 根因（已查證）
排程貼文在臉書後台被改晚；計時器確認發布被拒（讀取權限）→ 依 11/23 規則直接留言 → 對排程中貼文留言臉書回 100-33 → 1.5 分鐘通知、約 7.5 分鐘標失敗不再試。

## 已定案的決定
| 項目 | 決定 |
|---|---|
| 到點流程（排程發布，非影片） | 直接留言；100-33 才查貼文狀態（影片維持先查再留） |
| 查到未發布＋新時間 | 改等新時間、次數歸零、不通知 |
| 查到未發布沒新時間／已發布仍失敗 | 照重試，第一次失敗後 2 分鐘沒成功就通知發文者 |
| 讀取被拒 | 馬上通知系統管理者＋notify 權限組（系統訊息，同粉專 24 小時一次）、錯誤紀錄 `read_denied`；發文者照 2 分鐘規則 |
| 貼文已刪除 | 留言取消、不通知、操作紀錄寫一筆（系統偵測） |
| 24 小時等待 | 不做；一律 2 分鐘沒成功就通知 |
| 重試時間 | 到點、+30、+60、+120（第 4 次失敗＝2 分鐘→通知）、+360（最後） |
| 列表校正 | 已排程時間不同→改計時器時間（100-33 失敗的也恢復）；已發佈出現→計時器還在等或 100-33 失敗就馬上留 |
| 自動刷新 | 已排程、已發佈每 10 分鐘，自動只讀第一批 50 則 |
| 錯誤紀錄 | 加「複製」按鈕（時間、工具、粉專＋ID、摘要、連結、錯誤說明、臉書原文） |
