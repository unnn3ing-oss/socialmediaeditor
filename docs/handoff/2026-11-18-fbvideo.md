# 影片發布（多粉專上傳影片，新工具 `tools/fbvideo/`）
- 狀態：進行中　- 分支：claude/modest-mayer-dmxfhx　- 最後更新：2026-11-18
- 使用者原始需求：「與排程發布功能相同，但是作為多粉專上傳影片的功能，並且可以抓取檔案名稱作為標題，會帶入【標題】」；「獨立開一個在排程發布工具下方的工具，後端架構可共用，但前端是獨立」。依據使用者上傳的交接文件 C 段（Meta 影片發布）。

## 已定案的決定
| 項目 | 決定 | 理由 |
|---|---|---|
| 工具 | 新工具 `fbvideo`「影片發布」，registry 排在 `fbpost` 後；前端獨立（不 import fbpost 的模組，純函式需要就複製） | 使用者要求 |
| 權限 | 沿用 `server/fb/access.js` `fbAccess`（送出要 `post`，列表 `view`） | 後端共用 |
| 上傳到臉書 | **每個粉專各自工作階段，不經 R2、不用檔案代號**。橫式：`graph-video.facebook.com/{page}/videos` `upload_phase=start→transfer→finish`（finish 帶 title、description、排程）；Reels：`/{page}/video_reels` start → 傳到 `upload_url`（`rupload`，header `Authorization: OAuth`、`offset`、`file_size`）→ finish（`video_state=PUBLISHED`／`SCHEDULED`＋時間） | 使用者查到並指定 |
| 只上傳一次（方案乙） | 瀏覽器每段只送一次，後端轉給所有粉專。後端回「下一段要的範圍」＝所有粉專裡最小的 start，end＝和這個 start 相同的粉專要的最大 end（Reels 自訂 16MB），上限 32MB。offset 不同的粉專會落後、之後自己追上（自然退回各自上傳） | 使用者選乙 |
| 發布時機 | 「影片傳完」＋「按下送出」都成立才 finish；先按送出→後端存文案，最後一段傳完時後端自己 finish | 使用者要求 |
| 狀態 | `uploading`→`uploaded`→（送出）`processing`／`scheduled`／`published`；`failed`、`unknown`（結果不明＝待確認，不重送）、`stopped`、`canceled`；處理進度用 `GET /{video_id}?fields=status` | 交接文件 C |
| 上傳中保護 | 上傳中取消勾粉專、移除影片、取消勾影片 → 擋下並提示「影片上傳中，等上傳完成才能…（或先按『停止上傳』）」；關分頁 `beforeunload`；切工具／回首頁 外殼先確認（SDK `tb.busy(訊息或 null)`）；有「停止上傳」按鈕（確認後橫式送 `upload_phase=cancel`、Reels 放棄） | 使用者要求 |
| Reels 判斷 | 檔名開頭 `Reels_`／`Shorts_`（不分大小寫）或影片高＞寬 → Reels；可手動切；Reels 超過 90 秒黃字提醒 | 使用者要求 |
| 標題 | 檔名去副檔名，去內建 `Reels_`、`Shorts_` 前綴＋管理頁自訂前綴／後綴；同時填臉書 `title` 欄位 | 使用者要求 |
| 貼文內容 | **單一大框**。預設：第 1 行空白（小編文）／`【標題】`／hashtag 行／授權行。定位點＝第一個 `【…】` 行：hashtag 行＝標題下一行（`#` 開頭），授權行＝上次帶入的授權文字那行，找不到就插在 hashtag 行（或標題）下一行；找不到標題行改用固定第 3／4 行並黃字提醒 | 使用者選單一大框 |
| Reels 自動 hashtag | **只有檔名開頭 `Reels_`** 才自動加（預設 `#焦點新聞影音都在TVBS`，管理頁可改） | 使用者 |
| hashtag 按鈕 | 管理頁設定（≤20 個），按了加到 hashtag 行尾（空格分隔、不重複），再按移除 | 使用者 |
| 影片授權 | 輸入框，照原樣放進授權行；空白＝刪那行 | 使用者 |
| 多支影片 | 下拉列表勾選；每支自己的大框、hashtag、授權、時間；時間可「全部統一」或「各自」；粉專共用 | 使用者 |
| 留言 | 預設沒有；可加最多 3 則、可選活動留言（`/fb/presets`）；第 1 則「發布後 N 分」（0～1440），第 2、3 則距上一則 5 分倍數。不需要文章網址 | 使用者 |
| RD | 橫式 `純影/SLUG`、Reels `Reels/SLUG`；綠 `#38761d`、粗體、置中 → `/rundown` entries 加選填 `style:'video'`，Apps Script 需貼補丁（`docs/rundown-gs-video-style.md`），**使用者自行貼到 -schedulenewnet 的 rundown.gs 並重新部署** | 使用者選 A |
| 列表 | 只顯示本工具送出的工作（D1），含狀態 | 使用者 |
| 管理頁 | 「臉書發文」分類加「影片設定」卡片：標題前綴／後綴、Reels 自動 hashtag、hashtag 按鈕；存 D1 `fb_settings` k=`video` | 使用者 |

## API（前端 ↔ 後端）
- `GET /fb/video/settings` → `{ prefixes[], suffixes[], reelsTag, tags[] }`（view）
- `POST /fb/video/start` JSON `{ uploadId(32 hex), name, size, kind:'video'|'reel', pages:[id] }` → 對還沒開過的粉專開工作階段；回 `{ next:{start,end}|null, jobs:[…] }`（post）
- `POST /fb/video/chunk?u=<id>&start=<s>` body＝那段二進位 → 轉給要這段的粉專；回同上（全部傳完且已送出 → 自動 finish）
- `POST /fb/video/publish` JSON `{ uploadId, title, description, at:null|秒, comments:[{message,delay}] }` → 存文案；已傳完的粉專立刻 finish；回 jobs
- `POST /fb/video/stop` `{ uploadId }`；`POST /fb/video/drop` `{ uploadId, page }`（只在沒在上傳、沒送出時）
- `GET /fb/video/status?u=<id>` → 更新處理中的狀態（查臉書）後回 jobs
- `GET /fb/video/jobs` → 最近 7 天的工作（列表）
- job：`{ page, kind, state, videoId, at, title, error, sent }`；不回 token、session、upload_url
