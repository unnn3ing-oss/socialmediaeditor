# 交接檔（handoff）— 給接手的 AI 看

**用途**：任一個 AI 對話的用量用完時，另一個 AI（或新對話）讀交接檔就能接著做，不用重新問使用者。

## 什麼時候寫
1. 使用者確認「開始」後、**動手改程式前**：寫好、commit、推到開發分支。
2. 做完一個段落、或用量快用完：更新同一份再推。
3. 版本併入 main 後：交接檔留著當紀錄，在檔頭把狀態改成「已完成」。

## 接手的人怎麼用
1. `git fetch origin <分支> && git checkout <分支>`
2. 讀 `CLAUDE.md`（流程規則）→ 讀這份交接檔 → 只讀交接檔列出的檔案。
3. 從「下一步」的第一個未勾選項目開始；**不要重做已勾選的項目**，也不要重新討論「已定案的決定」。

## 格式（照這個順序，保持精簡）

```markdown
# <主題>
- 狀態：進行中／已完成　- 分支：claude/xxx　- 最後更新：YYYY-MM-DD
- 使用者原始需求：（一兩句，引用原話）

## 已定案的決定
| 項目 | 決定 | 理由 |

## 做法（改哪裡）
| 檔案 | 內容 | 狀態（✅ 完成／🚧 進行中／⬜ 未開始） |

## 下一步
- [ ] 具體到檔案與函式的步驟

## 測試
要跑哪些指令、預期結果。

## 注意事項／不能做的事
```
