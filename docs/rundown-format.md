# 更新 Rundown 寫入格式

這次格式變更要更新目前使用的 **Google Apps Script**。推送網站、部署 Cloudflare Worker 或只在 Apps Script 按儲存，都不會更新既有 `/exec` 部署的版本。

## 修改內容

- 填入的稿件文字水平置中，沿用既有 `RD_STYLE` 字級、粗體與紫色設定。
- 真正新增的時間碼水平置中、`#4285f4`、粗體，包含就地補碼及插入後補碼。
- 既有稿件／時間碼仍依原規則連同格式向下移動。沒有時間碼時不填假碼，也不批次重設整欄或其他儲存格格式。

## 更新既有指令碼與部署

1. 用原本擁有部署權限的 Google 帳號，開啟目前處理 Rundown 的 Apps Script 專案。先保留原始碼副本。
2. 開啟本倉庫的 [rundown-format.gs](../server/gas/rundown-format.gs)。這是**替換片段，不能獨立部署**：用其中的 `rdAddOne` 完整替換專案內原有的同名函式，並在專案中加入一次 `rdWriteTimeCode`。不要保留兩份同名函式，也不要把這段當成全份程式覆蓋原專案。
3. 保留原有 `doPost`、`rdPlan` 等其餘函式、`RD_STYLE`、驗證流程，以及指令碼屬性中的既有設定。不要把試算表 ID 或金鑰貼進倉庫、聊天或文件。
4. 儲存後，選 **部署 → 管理部署 → 原本的網頁應用程式 → 編輯**，版本選 **新增版本**，再按 **部署**。沿用原部署的執行身分、存取設定與 `/exec` 網址；本次不建立另一個新部署。
5. 因為沿用原 `/exec` 網址，Cloudflare 的 Rundown 網址與金鑰不需因本次格式修改而變更。

## 驗證

工具內的「測試連線」只能確認連得上 Apps Script，不能證明新格式已部署。更新後，在下一次原本就要送出的正常排程成功寫入 RD 時，檢查該稿件儲存格是否水平置中，新填入的分鐘碼是否為藍色 `#4285f4` 且粗體；這次沒有新增時間碼時，不應期待原有其他格子的顏色被改掉。

本倉庫以模擬 Spreadsheet 物件測試定位、寫入、插入、清空與格式呼叫，未修改正式試算表，也未從此環境部署 Google Apps Script。實際格式需完成上述 Google 部署步驟後才會生效。
